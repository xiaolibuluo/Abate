## 1. 六阶段路线图

| 阶段 | 目标 | 周期 | 交付物 |
|------|------|------|--------|
| P0 地基 | 项目骨架 + 模型抽象层 + Agent 运行时核心 | 2 周 | 可编译的空壳应用 + 单 Agent 跑通 |
| P1 最小团队 | CEO + 架构师 + 前端 + 逻辑 + 构建 5 Agent | 2 周 | 5 Agent 协作产出简单应用 |
| P2 完整团队 | 全部 23 Agent + 工具隔离 + 权限矩阵 | 3 周 | 完整团队协作产出中等应用 |
| P3 混沌自测 | Abate 引擎移植 Android + 30 插件适配 | 2 周 | 内置混沌测试可用 |
| P4 本地模型 | ONNX Runtime 集成 + 端侧推理 + 离线模式 | 2 周 | 本地模型可用 |
| P5 打磨 | 性能优化 + UI 打磨 + 安全审计 + 发布准备 | 2 周 | 可发布版本 |

总周期：约 13 周

## 2. P0 地基（第 1-2 周）

### 交付物
- Android 项目骨架（Kotlin + Compose + Hilt）
- Model Abstraction Layer（统一接口 + API 适配器）
- Agent Runtime 核心（单 Agent 执行引擎）
- Room 数据库 schema
- 基础 UI 框架（导航 + 主题）

### 验收标准
- 应用可编译可启动
- 单个 Agent 可调用 API 模型完成简单任务
- Room 数据库可读写

## 3. P1 最小团队（第 3-4 周）

### 交付物
- CEO Agent（需求解析）
- 架构师 Agent（模块拆分）
- 前端 Agent（Compose UI 生成）
- 逻辑 Agent（业务代码生成）
- 构建 Agent（Gradle 打包）
- Orchestrator 基础版（DAG 编排）

### 验收标准
- 5 Agent 协作产出一个 Hello World 应用
- DAG 编排正确执行依赖关系
- 用户可在控制台查看 Agent 状态

## 4. P2 完整团队（第 5-7 周）

### 交付物
- 全部 23 个 Agent 角色
- Tool Registry + 权限矩阵
- WASM 沙箱集成
- 审计日志系统
- 消息总线
- 设计部 3 Agent + QA 部 4 Agent + 安全部 3 Agent + 运维部 3 Agent

### 验收标准
- 23 Agent 协作产出中等复杂度应用
- 权限矩阵强制生效
- 审计日志完整记录

## 5. P3 混沌自测（第 8-9 周）

### 交付物
- Abate injector/probe/reporter 移植到 Kotlin
- 30 个测试插件适配 Android
- 6 类故障注入器 Android 版
- 混沌 Agent 集成
- 120 条 CES 规范内置

### 验收标准
- 混沌 Agent 可注入 6 类故障
- 30 插件可运行并输出报告
- Agent 生成的应用经过混沌测试验证

## 6. P4 本地模型（第 10-11 周）

### 交付物
- ONNX Runtime 集成
- MLC-LLM 集成
- 用户模型上传/加载
- 智能路由器
- 离线模式

### 验收标准
- 本地模型可推理
- 离线模式下 Agent 可工作
- 智能路由正确切换 API/本地模型

## 7. P5 打磨（第 12-13 周）

### 交付物
- 性能优化（启动时间 <3s，内存 <256MB）
- UI 打磨（Material 3，暗色模式，动画）
- 安全审计（沙箱逃逸测试，权限审查）
- 发布准备（签名，ProGuard，版本管理）

### 验收标准
- 通过全部 30 个混沌测试插件
- 安全审计无高危漏洞
- 应用可签名发布
