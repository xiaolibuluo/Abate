# Abate 混沌实验规范（Chaos Experiment Specification, CES）v0.1

> 品牌：Abate · 止息混沌
> 开源方：小黎的部落（www.qingdujian.com）
> 许可：AGPLv3；商业用途须事先获得小黎的部落书面授权
> 地位：本规范是质量工程的『度量衡』。实现可互换，规范保持守恒。
> 范围：v0.1 起覆盖双内核——动态扰动（混沌实验，第 1-8 章）与静态扰动（变异实验，第 9 章），统一于 HPOV 扰动代数。

## 第 0 章 · 前言与治理

### 0.1 规范地位
- CES 定义扰动实验的通用语言、执行语义、评分算法与认证方法：动态扰动即混沌实验，静态扰动即变异实验，两者统一于 HPOV 范式（假设 Hypothesis → 扰动 Perturbation → 观测 Observation → 判定 Verdict）。
- 任何符合 CES 的实现称为 CES Compatible 实现；Abate 参考引擎是首个实现，但不是唯一实现。
- 规范条款一经发布，编号永久有效，只可标记废弃，不得回收复用。

### 0.5 扰动代数与统一判定
- [CES-0.5.1] 一切变异体与一切混沌故障都是扰动（Perturbation）：变异是静态扰动，混沌是动态扰动。
- [CES-0.5.2] 判定语义统一为两值：Contained（被观测网控制）与 Escaped（逃逸出观测网）。变异体被测试杀死 = Contained，存活 = Escaped；稳态保持 = Contained，破坏 = Escaped。
- [CES-0.5.3] 100% 全量覆盖的数学定义：Escaped = 0。
- [CES-0.5.4] 统一质量分 TQS = 变异分 × 混沌分 × 覆盖分的几何聚合（整数立方根），任一层为零则总分为零；门禁判定三层独立达标，不允许长板补偿短板。

### 0.2 版本策略
- 年度 LTS 节奏；语义化版本 MAJOR.MINOR.PATCH。
- v1.0 起规范冻结：只增不改，新增条款向后兼容。
- 兼容承诺写入 GOVERNANCE， maintainer 无权单方面更改。

### 0.3 RFC 流程
- 规范变更需提交 RFC：动机、条款草案、影响分析。
- 硬性门槛：两个独立实现佐证可行性 + 不少于 30 天公示期。

### 0.4 许可与商业授权
- 规范文本与参考实现以 AGPLv3 发布。
- 任何商业用途（含以 SaaS 形式对外提供基于 Abate 的服务）须获得小黎的部落书面授权。

## 第 1 章 · 术语与故障分类学

### 1.1 设计依据
故障域是守恒的：延迟、崩溃、网络分区、资源耗尽、数据损坏、时钟漂移——该分类学三十年未变，是规范十年不维护的根基。平台 API 的变化一律隔离在适配器层（第 7 章）。

- [CES-1.1.1] 本章的故障编码与术语构成规范守恒层：一经发布，语义不得修改，只可增补条目；新增条目不得与既有条目语义重叠。
- [CES-1.1.2] 实现方、适配器与工具链在一切面向用户的输出（DSL、API、报告、日志、错误码、徽章）中必须使用本章定义的编码与术语，禁止自创同义词。

### 1.2 故障六分类（编码永久固定）
| 编码 | 分类 | 定义 | 典型参数 |
|---|---|---|---|
| F1 | Latency 延迟 | 调用、I/O、调度的时延注入与抖动 | delay、jitter、percent |
| F2 | Crash 崩溃 | 进程、实例、组件的终止与重启 | signal、gracePeriodMs |
| F3 | Partition 分区 | 网络断连、丢包、DNS 污染、路由隔离 | loss、direction、peer |
| F4 | Exhaustion 耗尽 | CPU、内存、磁盘、文件描述符、连接池耗尽 | resource、utilization、fillRate |
| F5 | Corruption 损坏 | 数据位翻转、乱序、重复、丢失 | bitRate、pattern |
| F6 | ClockSkew 时钟漂移 | 系统时钟偏移与回拨 | offsetMs |

- [CES-1.2.1] 一切动态扰动故障必须归入 F1–F6 之一；无法归类的故障不得注入，须先按 0.3 提交 RFC 扩充分类学。
- [CES-1.2.2] 复合故障以故障序列表达，禁止创设混合类编码；序列中每个元素独立声明编码与参数，独立计入覆盖矩阵。
- [CES-1.2.3] 故障编码在 DSL、API、报告、错误码与适配器能力声明中逐字一致，区分大小写。

### 1.3 子编码
- 六分类之下允许注册子编码（如 F3.dns、F4.fd），子编码表维护于附录 B（ChaosHub 分类编码）；新增子编码走 MINOR 版本流程，不触动守恒层。
- [CES-1.3.1] 子编码格式为『{F编码}.{小写字母或数字}』，全局唯一；适配器映射不完整时按第 7 章显式降级声明，不得静默归入父编码。

### 1.4 标准术语表
一词一义；术语、错误码、测试名、文档四处互链。下表为规范强制术语：

| 术语 | 英文 | 定义 |
|---|---|---|
| 实验 | Experiment | 一次完整的 HPOV 闭环（假设→扰动→观测→判定），规范最小可执行单元 |
| 稳态假设 | Steady-State Hypothesis | 注入窗口内应持续成立的 SLI 断言集合；实验的可证伪命题 |
| 爆炸半径 | Blast Radius | 扰动允许波及的最大范围，以实例数、时长、流量比例三维上界声明（CES-2.5.1） |
| 红线 | Abort Condition | 触发即无条件迁移 Recovering 的停止条件，无人工旁路（CES-3.1.1） |
| 弱点 | Weakness | 实验中检出并可复现的缺陷，具备第 6 章规定的生命周期状态 |
| 回归演练 | Regression Drill | 针对已修复弱点的周期性重放实验，防止弱点复活 |
| 证据等级 | Evidence Level | 观测方法严谨度分级 A/B/C（第 5 章），决定实验权重折抵（CES-4.3.1） |
| 关键度 | Criticality | 目标业务重要度，整数 1–5，实验权重的乘数因子（CES-4.3.1） |
| 种子 | seed | 确定性重放的全局随机源：同一实验定义 + 同一 seed 必产生同一故障序列（CES-3.1.3） |
| 观测网 | Observation Mesh | 实验声明的全部 SLI 断言、数据不变量与红线的集合；Escaped 判定的边界 |
| 判定 | Verdict | 实验终态结论，统一两值语义 Contained / Escaped（CES-0.5.2） |
| 适配器 | Adapter | 将第三方执行后端能力映射至 F1–F6 编码的插件（第 7 章），规范中唯一允许随上游演进的部分 |

- [CES-1.4.1] 术语表禁止一词多义与一义多词；实现输出中的同义表述视为文档缺陷。
- [CES-1.4.2] 每个术语必须可反向检索：术语 → 规范条款 → 认证用例 → 错误码，四链齐备方可进入术语表。

## 第 2 章 · 实验模型（DSL 规范）

### 2.1 载体与语法子集
- 声明式 YAML；文件以 .abate.yaml 为推荐后缀。
- 顶层五元组为强制结构：target / fault / blastRadius / steadyState / abortOn。
- [CES-2.1.1] 实现方不得因未知字段拒绝实验文件（向前兼容预留）。
- [CES-2.1.2] 校验失败必须输出结构化错误：字段路径 + 期望 + 实际 + 规范条款号。
- [CES-2.1.3] 规范 DSL 为行式严格 YAML 子集：两空格缩进表达层级，仅含映射、标量与列表项，嵌套深度不超过三层（顶层 → 节 → 列表项字段）；流式语法（花括号与方括号）、锚点、别名、多文档标记不在子集内，实现方必须拒绝并报结构化错误。
- [CES-2.1.4] 数值字段一律为十进制整数：时长以毫秒计（windowMs、maxDurationMs、recoveryBudgetMs），比率以万分位计（maxTraffic）；数值字段携带单位后缀（ms、m、%）属结构化错误。

### 2.2 顶层字段与目标寻址
顶层字段：

| 字段 | 类型 | 必填 | 语义 |
|---|---|---|---|
| id | string | 是 | 实验唯一标识，聚合排序键（CES-4.1.3） |
| seed | int64 | 是 | 确定性重放种子（CES-3.1.3） |
| criticality | int | 是 | 目标关键度 1–5（CES-4.3.1） |
| recoveryBudgetMs | int64 | 否 | 恢复预算，缺省 300000（CES-4.4.2） |
| target | 节 | 是 | 作用目标（本节） |
| fault | 节 | 是 | 注入故障（2.3） |
| blastRadius | 节 | 是 | 爆炸半径（2.5） |
| steadyState | 列表 | 是 | 稳态断言集（2.6） |
| abortOn | 列表 | 否 | 红线集（2.7） |
| params | 节 | 否 | 实现方扩展参数，属 CES-2.1.1 容忍域 |

- [CES-2.2.1] target 支持服务、实例、依赖面三类寻址；选择器语义必须确定性。
- [CES-2.2.2] target.kind 取值限定 service / instance / dependency；target.name 必填非空；kind 与 name 之外的键值对构成选择器。
- [CES-2.2.3] 选择器为键值等值匹配，多键之间逻辑与；匹配结果必须按字典序稳定排序，同一实验文件在任何合规实现上必须解析出同一目标集合。

### 2.3 故障定义
- [CES-2.3.1] fault.type 必须使用第 1 章分类编码；参数集合按分类定义。
- [CES-2.3.2] fault.type 之外的键值对构成故障参数，参数集必须非空；键与值均为字符串以保证跨插件可序列化；参数合法性按附录 B 分类参数表与执行后端能力声明核验。

### 2.4 注入语义
- [CES-2.4.1] 注入动作幂等：重复执行不产生叠加效果。

### 2.5 爆炸半径
- [CES-2.5.1] blastRadius 必须声明实例上限、时长上限、流量比例上限三者至少其二。
- [CES-2.5.2] 三维上限字段为 maxInstances（实例数）、maxDurationMs（毫秒）、maxTraffic（万分位）；未声明维度按无上界处理，Preflight 必须将其标记为风险项并记录。

### 2.6 稳态断言
- [CES-2.6.1] steadyState 至少一条 SLI 断言；断言含指标源、窗口、阈值、统计方法。
- [CES-2.6.2] 断言字段：sli（指标源标识）与 assert（阈值表达式）必填，method（统计方法标识）与 windowMs（统计窗口毫秒）可选；assert 求值结果必须归一为万分位整数参与评分（CES-4.1.2）。

### 2.7 红线
- [CES-2.7.1] abortOn 红线触发即进入 Recovering，无人工旁路。
- [CES-2.7.2] abortOn 断言结构与 steadyState 相同（CES-2.6.2）；abortOn 为空时爆炸半径与稳态断言仍然强制，红线监控由实现方安全策略兜底并在报告中声明。

### 2.8 规范示例
以下示例可通过参考实现 dsl.Parse 解析并通过全部校验（数值字段均为整数，CES-2.1.4）：

```yaml
id: order-service-latency
seed: 20260101
criticality: 4
recoveryBudgetMs: 300000
target:
  kind: service
  name: order-service
  env: staging
fault:
  type: F1
  delay: 500
  jitter: 100
  percent: 3000
blastRadius:
  maxInstances: 1
  maxDurationMs: 300000
  maxTraffic: 1000
steadyState:
  - sli: http_success_rate
    assert: ">= 99.9%"
    method: rate
    windowMs: 60000
abortOn:
  - sli: error_rate
    assert: "> 5%"
    method: rate
    windowMs: 10000
```

## 第 3 章 · 执行语义与状态机

### 3.1 生命周期
Pending → Preflight → Injecting → Observing → Recovering → Verdict。状态迁移表为规范强制内容，非法迁移视为实现缺陷。

状态定义：

| 状态 | 定义 |
|---|---|
| Pending | 实验已受理，等待准入检查 |
| Preflight | 准入检查中：目标可达性、爆炸半径合规、观测网与凭证就绪 |
| Injecting | 故障注入进行中（注入动作幂等，CES-2.4.1） |
| Observing | 稳态观测中：SLI 断言、数据不变量与红线持续监控 |
| Recovering | 回滚与残留清理中 |
| Verdict | 终态：判定完成，产出报告 |

合法迁移表（强制）：

| 源状态 | 合法目标状态 |
|---|---|
| Pending | Preflight；Verdict（准入前取消，判定 CANCELLED） |
| Preflight | Injecting；Recovering（红线触发）；Verdict（准入失败，判定 REJECTED） |
| Injecting | Observing（注入窗口结束）；Recovering（红线触发） |
| Observing | Recovering（观测结束或红线触发） |
| Recovering | Verdict |
| Verdict | 无（终态，无出边） |

- [CES-3.1.5] 实验初始状态必须为 Pending；Verdict 为唯一终态，任何实现不得为 Verdict 定义出边。
- [CES-3.1.6] 实现方必须拒绝上表之外的状态迁移，并以结构化错误记录源状态、目标状态与触发事件；发生表外迁移视为实现缺陷。
- [CES-3.1.7] 每次状态迁移必须记录时间戳与触发原因；实验时间线必须支持完整重建状态序列，供第 6 章报告与附录 A 模型对拍。

### 3.2 不变量
- [CES-3.1.1] 任何状态下红线触发必须迁移至 Recovering；适用状态为 Preflight、Injecting、Observing，Recovering 与 Verdict 中的红线事件只记录、不再迁移（恢复流程不可重入）。
- [CES-3.1.2] Recovering 完成后不得残留任何注入副作用；残留须可被机器扫描检出。
- [CES-3.1.3] 同一实验定义 + 同一 seed 必须产生可重放的故障序列（确定性重放）。
- [CES-3.1.4] Preflight 不通过不得进入 Injecting；准入失败原因必须结构化记录。

### 3.3 判定结果
Verdict 状态的判定结论取四值：

| 判定 | 语义 |
|---|---|
| CONTAINED | 扰动被观测网控制：稳态假设在注入窗口内保持（对应 CES-0.5.2 的 Contained） |
| ESCAPED | 扰动逃逸出观测网：稳态破坏或数据不变量违反，弱点检出（对应 CES-0.5.2 的 Escaped） |
| REJECTED | Preflight 准入失败，实验未执行注入 |
| CANCELLED | 准入前由操作方取消，实验未执行注入 |

- [CES-3.3.1] 判定结果取值限定上表四值；实现方不得扩展判定取值，附加信息以弱点清单与报告字段表达。
- [CES-3.3.2] REJECTED 与 CANCELLED 不属于第 4 章所称『已执行实验』，不计入任何维度的权重求和，但必须在报告中逐项列明。
- [CES-3.3.3] ESCAPED 判定必须关联至少一条弱点记录或红线事件；禁止无证据判定。

### 3.4 形式化
- 状态机与不变量以 TLA+/Quint 建模，模型文件作为附录 A 强制发布。
- 实现方须通过附录 A 的模型检验导出用例。
- [CES-3.4.1] 附录 A 模型必须覆盖本章全部状态、迁移表与不变量；模型与正文冲突时，冲突期间以更严格者为准，并须在下一修订消除歧义。
- [CES-3.4.2] L1 认证套件（第 8 章）必须包含附录 A 导出的全部模型检验用例，且用例执行结果确定性可复现。

## 第 4 章 · 可靠性评分算法（数学定义）

### 4.1 总则
- [CES-4.1.1] 可靠性总分 Score ∈ [0.00, 100.00]，由五个维度加权求和得出，展示精度固定为小数点后两位。
- [CES-4.1.2] 全部评分计算必须使用万分位（‱）定点整数运算：实现方禁止在评分链路中使用浮点数，以消除跨语言、跨平台的舍入漂移。
- [CES-4.1.3] 聚合前，实验记录按实验 ID 字典序升序排序；所有乘法先于除法执行；整数除法向零取整。相同输入在任何合规实现上必须产生相同输出（可复算承诺）。

### 4.2 维度与权重
| 维度 | 符号 | 权重（‱） |
|---|---|---|
| 可用性韧性 | AR | 3000 |
| 恢复速度 | REC | 2000 |
| 降级能力 | DC | 2000 |
| 数据一致性 | DI | 2000 |
| 爆炸半径控制 | BRC | 1000 |

- 所有维度分值以万分位表示：满分 = 10000（即 100.00 分）。
- [CES-4.2.1] Score_raw = (AR×3000 + REC×2000 + DC×2000 + DI×2000 + BRC×1000) ÷ 10000，结果仍为万分位分值。

### 4.3 实验权重
- [CES-4.3.1] 实验 e 的权重 w_e = c_e × e_e。
  - c_e：目标关键度，整数 1–5，由实验声明并附依据，认证套件核验声明与拓扑的一致性；
  - e_e：证据等级系数（定义见第 5 章）：A = 10000，B = 8000，C = 5000。
- [CES-4.3.2] 低严谨度证据必须折抵权重，不得与高严谨度证据获得相同计分地位。

### 4.4 维度公式
约定：时长为毫秒整数；比率为万分位整数。

#### 4.4.1 可用性韧性 AR
- hold_e =（注入窗口内全部稳态 SLI 同时成立的累计毫秒数）× 10000 ÷（注入窗口总毫秒数）。
- [CES-4.4.1] AR = Σ(w_e × hold_e) ÷ Σ(w_e)，覆盖全部已执行实验。

#### 4.4.2 恢复速度 REC
- T_e = 红线触发（或注入停止）到全部 SLI 回落基线并持续 60s 的毫秒数；T_budget 为实验声明的恢复预算（缺省 300000ms）。
- s_e = max(0, 10000 − T_e × 10000 ÷ T_budget)。
- [CES-4.4.2] REC = Σ(w_e × s_e) ÷ Σ(w_e)，仅统计发生过恢复事件的实验；无恢复事件时本维度按缺测处理（见 4.6）。

#### 4.4.3 降级能力 DC
- 仅适用于依赖失效类实验（F3 作用于依赖面）。
- f_e：降级开关在注入后 10s 内激活取 10000，否则取 0（须机器可检）。
- q_e = 降级模式达标请求数 × 10000 ÷ 降级模式总请求数。
- DC_e = f_e × q_e ÷ 10000。
- [CES-4.4.3] DC = Σ(w_e × DC_e) ÷ Σ(w_e)。

#### 4.4.4 数据一致性 DI
- d_e = 通过的不变量数 × 10000 ÷ 不变量总数（对账、约束、幂等性校验）。
- [CES-4.4.4] 硬规则：任一实验检出不可调和数据丢失，DI 维度封顶 2000（20.00 分）。
- DI = min(Σ(w_e × d_e) ÷ Σ(w_e), 触发硬规则时为 2000)。

#### 4.4.5 爆炸半径控制 BRC
- r_e = min(10000, 声明半径 × 10000 ÷ 实际观测半径)；观测半径为 0 时取 10000。
- [CES-4.4.5] 红线响应时延超过声明上限的实验，r_e 直接取 0。
- BRC = Σ(w_e × r_e) ÷ Σ(w_e)。

### 4.5 覆盖修正
- C = 已演练组合数 × 10000 ÷『服务 × 故障分类 × 依赖面』覆盖矩阵总组合数；目标比率 M = 9500（即 95%）。
- 修正系数 k = 8000 + 2000 × min(C, M) ÷ M。
- [CES-4.5.1] Score_final = Score_raw × k ÷ 10000。覆盖率达 95% 时 k = 10000，无惩罚；零覆盖时最低保留 80%。
- [CES-4.5.2] ChaosHub TOP 20 高频故障模式为覆盖矩阵必测项：未演练的 TOP 20 项在 C 的分子中计 0，并须在报告中逐项列出。

### 4.6 缺测维度
- [CES-4.6.1] 缺测维度按 0 分计入总分，并在报告中以 UNMEASURED 标记；该规则与 95% 覆盖目标联动，驱动演练计划补齐缺口。

### 4.7 舍入与展示
- [CES-4.7.1] 展示分 = Score_final ÷ 100，整数位为分、余数两位为小数；万分位整数天然精确到 0.01 分，全程无舍入误差。
- [CES-4.7.2] 报告必须同时输出：Score_final、五维度原值、C、k、缺测维度清单。

### 4.8 冻结条款
- [CES-4.8.1] v1.0 后本章公式只可增补维度或修正笔误；任何行为变更须升 MAJOR 版本。
- [CES-4.8.2] 附录 C 金标准数据集与本章公式具有同等效力：实现方对金标准输入的计算结果必须与公布值完全一致。

### 4.9 基准与徽章
- 评分附行业匿名基准分位（数据来自 ChaosHub，opt-in）。
- 徽章嵌入规范：README 徽章数据必须由认证实现产出。

## 第 5 章 · 观测与判定

### 5.1 证据等级
| 等级 | 方法 | 适用 | 权重系数 e_e |
|---|---|---|---|
| A | 控制组对比 + 显著性检验（如差分中的差分） | 生产与高利害判定 | 10000 |
| B | 单组时序基线对比 | 预发与常规演练 | 8000 |
| C | 阈值判定 | 冒烟与开发自测 | 5000 |
- [CES-5.1.1] 报告必须声明证据等级；声称因果结论必须使用 A 级。
- [CES-5.1.2] 证据等级映射实验权重系数 e_e（CES-4.3.1）；实现方不得按高于实际观测方法的等级计权。
- [CES-5.1.3] 声明等级高于实际观测方法时，认证套件按实际方法降级定级，并将偏差记入合规报告。

### 5.2 红线响应
- [CES-5.2.1] 红线触发到注入停止的响应时延上限：实现方须在文档中声明，认证套件实测核验。
- [CES-5.2.2] 响应时延定义为红线条件首次成立时刻到注入停止指令生效时刻的毫秒差；测量必须机器可采并计入报告时间线（CES-3.1.7）。
- [CES-5.2.3] 响应时延超过实验声明上限或实现方声明上限的实验，BRC 维度按 CES-4.4.5 处理（r_e 取 0）。

### 5.3 观测网与采样
- [CES-5.3.1] 观测网由稳态断言集（steadyState）、数据不变量集（5.4）与红线集（abortOn）构成；观测网即 Escaped 判定的边界（第 1 章术语）。
- [CES-5.3.2] 采样顺序与采样点由 seed 驱动的确定性 RNG 决定（CES-3.1.3）；同一实验定义 + 同一 seed 的重放必须产出逐点一致的观测序列。
- [CES-5.3.3] SLI 断言在 windowMs 窗口内按 method 统计求值，与 assert 阈值比较得出成立/不成立；求值与比较全程使用万分位定点整数（CES-4.1.2）。
- [CES-5.3.4] 观测数据缺失（指标源不可达或窗口内无样本）时断言按不成立处理并在报告标记 DATA_MISSING；禁止静默跳过或插补。

### 5.4 数据不变量
- [CES-5.4.1] 数据不变量（对账、约束、幂等性校验）在 Recovering 完成后执行全量核验，结果计入 DI 维度（CES-4.4.4）。
- [CES-5.4.2] 不变量核验必须可重放：核验输入、数据快照标识与结果计入报告（CES-6.1.1）。

## 第 6 章 · 报告格式

### 6.1 结构化 Schema
- JSON 为规范格式：实验元信息、时间线、SLI 证据、判定结论、弱点清单、证据等级、seed。
- Markdown 为人类渲染层的推荐 profile；报告必须自包含、可脱机验证签核。

报告顶层字段（强制）：

| 字段 | 语义 |
|---|---|
| schemaVersion | 报告模式版本，本版取 ces/v0.1 |
| experiment | 实验元信息：id、seed、criticality、五元组全文、recoveryBudgetMs |
| timeline | 状态迁移时间线：每次迁移的时间戳与触发原因（CES-3.1.7） |
| observations | SLI 证据：断言原文、窗口、求值结果、DATA_MISSING 标记（CES-5.3.4） |
| invariants | 数据不变量核验结果（CES-5.4.1） |
| verdict | 判定结论：CONTAINED / ESCAPED / REJECTED / CANCELLED（CES-3.3.1） |
| weaknesses | 弱点清单（6.2） |
| evidenceLevel | 证据等级 A / B / C（CES-5.1.1） |
| score | 评分明细：Score_final、五维度原值、C、k、缺测维度清单（CES-4.7.2） |

- [CES-6.1.1] 报告必须含 seed 与全部重放所需参数。
- [CES-6.1.3] 顶层字段缺失或取值非法视为实现缺陷；报告中的未知字段按 CES-2.1.1 同等容忍原则处理。
- [CES-6.1.4] REJECTED 与 CANCELLED 实验的报告必须逐项列明，score 字段标记 NOT_SCORED（CES-3.3.2）。

### 6.2 弱点生命周期
- [CES-6.1.2] 弱点条目必须含生命周期状态：发现 → 归档 → 修复跟踪 → 回归验证 → 场景沉淀。
- [CES-6.2.1] 生命周期状态迁移单向不可逆；回归验证必须由回归演练（第 1 章术语）驱动，通过后方可进入场景沉淀。
- [CES-6.2.2] 弱点条目必须含：全局编号、关联实验 ID、关联判定（ESCAPED）、复现步骤或重放参数、当前状态与时间戳。

### 6.3 验证与签核
- [CES-6.3.1] 报告必须自包含：凭报告内数据可脱机复算判定与评分，不依赖任何外部服务。
- [CES-6.3.2] 报告必须含全文内容哈希（SHA-256）；签核链基于内容哈希构建，任何字段变更使既有签核失效。
- [CES-6.3.3] Markdown profile 是 JSON 源的渲染层，不得增删语义字段；两种形态必须指向同一 JSON 源并共享其内容哈希。

## 第 7 章 · 插件与适配器协议

### 7.1 插件协议 v1
- 进程隔离加载；握手时交换 protocolVersion，不兼容即拒绝并给出明确错误。
- 能力声明：插件启动时声明支持的故障编码（F1-F6）与目标类型。
- 错误码体系：E1xxx 稳定目录，每码一页文档（原因、影响、处置）。

- [CES-7.1.1] 插件以进程隔离加载；协议主版本为 v1，握手时交换 protocolVersion，与核心不一致即拒绝加载并返回明确错误（错误码 E1001，附录 D）。
- [CES-7.1.2] 能力声明字段：name（插件名）、version（插件语义化版本）、protocol（协议主版本）、faultClasses（支持的故障编码 F1–F6）、targetKinds（支持的目标寻址模式）；protocol 缺失或 faultClasses 为空的插件不得承接注入任务。
- [CES-7.1.3] 插件按角色分四类：Injector（注入与恢复）、Probe（SLI 采样）、Validator（准入与准出校验）、Reporter（报告产出）；一个插件可声明多角色，但每个角色必须完整实现该角色接口。
- [CES-7.1.4] Injector.Inject 对同一实验重复调用必须幂等（CES-2.4.1）；Recover 必须可重复调用且最终无残留（CES-3.1.2）；注入句柄含全局唯一标识与所属实验 ID。
- [CES-7.1.5] Probe.Observe 返回样本三元组：指标名、值（万分位比率或毫秒整数，含义按指标定义）、Unix 毫秒时间戳；采样时序由 seed 驱动（CES-5.3.2）。
- [CES-7.1.6] Validator.Preflight 返回的每个问题均为阻止实验的硬伤（CES-3.1.4）；Postflight 执行恢复验证与残留扫描（CES-3.1.2）。
- [CES-7.1.7] 错误码 E1xxx 为稳定目录：一经发布不得回收复用；每个错误码必须有一页文档（原因、影响、处置），目录全文见附录 D。

### 7.2 适配器规范
- 第三方执行后端（Chaos Mesh / Litmus / 云厂商 FIS 等）通过适配器接入。
- 适配器必须将其故障能力映射至第 1 章分类编码；映射不完整时必须显式降级声明。
- [CES-7.2.1] 适配器是规范中唯一允许随上游平台演进的部分，独立于核心版本节奏发布。
- [CES-7.2.2] 适配器能力声明必须逐项列出可完整映射至第 1 章编码的故障能力与目标寻址模式；无法完整映射的上游能力不得声明，只能显式降级。
- [CES-7.2.3] 适配器必须实现 Injector 角色；Probe、Validator、Reporter 角色允许由核心内置实现兜底，兜底情况必须在能力声明与报告中注明。
- [CES-7.2.4] 适配器版本独立于 CES 版本与核心版本节奏；适配器发布、升级与废弃不改变规范条款效力，废弃适配器须提前公告并给出迁移路径。

### 7.3 MCP Server 协议
- Abate 通过 MCP（Model Context Protocol）Server 以 JSON-RPC 2.0 over stdio 暴露变异测试与混沌工程能力，供 AI 编码助手与外部工具集成。
- [CES-7.3.1] MCP Server 协议版本为 `2024-11-05`，传输层为 JSON-RPC 2.0 over stdio；实现必须支持 `initialize`、`tools/list`、`tools/call` 三个方法，错误码遵循 JSON-RPC 2.0 标准（-32700/-32601/-32602/-32603）。
- [CES-7.3.2] 工具集必须包含 `generate_mutants`（变异体生成）、`apply_mutant`（变异体应用）、`list_fault_classes`（故障分类列举）；可选包含 `generate_test`（LLM 补测生成，依赖 CES-9.5.3 LLM 客户端接口）。
- [CES-7.3.3] `generate_test` 工具的 provider 参数必须支持 `openai` 与 `claude` 两种值；不支持 provider 必须返回错误，不得静默降级。

## 第 8 章 · 一致性认证

### 8.1 认证分级
| 级别 | 内容 |
|---|---|
| L1 | 确定性模拟器合规：在模拟器上跑全套规范测试用例 |
| L2 | 真实后端合规：至少一个真实适配器后端通过用例 |

- [CES-8.1.1] L2 认证以 L1 通过为前提；未通过 L1 的实现不得申请 L2。
- [CES-8.1.2] 认证结果绑定规范版本与插件协议主版本；实现升级核心版本后须重新认证，适配器升级不触发核心重认证（CES-7.2.1）。

### 8.2 认证套件
- 公开可跑：一条命令产出合规报告，结果确定性可复现。
- 模拟器为认证底座：纯软件数字孪生，不触碰真实平台 API，永不过时。

- [CES-8.2.1] 认证套件一条命令产出合规报告；同一实现版本 + 同一套件版本的重跑结果必须完全一致（确定性可复现，与 CES-3.1.3 同源纪律）。
- [CES-8.2.2] 认证底座为确定性模拟器，运行模式分 simulation / staging / production 三档；L1 认证在 simulation 档执行，不触碰真实平台 API。
- [CES-8.2.3] 套件必须覆盖：DSL 一致性用例（第 2 章）、状态机与不变量用例（第 3 章，含附录 A 模型检验导出用例，CES-3.4.2）、评分金标准数据集复算（附录 C，CES-4.8.2）、报告格式校验（第 6 章）。
- [CES-8.2.4] 任一用例失败即认证不通过；失败用例必须逐条列明并附条款号，不得部分通过。

### 8.3 徽章
- 仅通过认证的实现可挂 CES Compatible 徽章；徽章样式与核验 URL 规范另定。

- [CES-8.3.1] 徽章仅授予通过认证的实现，并标注认证级别（L1/L2）与规范版本；徽章数据必须由认证实现产出（CES-4.9）。
- [CES-8.3.2] 每枚徽章必须附核验 URL：访问返回该实现的认证报告内容哈希（CES-6.3.2）与套件版本；核验失败视为徽章失效。
- [CES-8.3.3] 认证过期或实现版本超出认证范围时，实现方必须在 30 日内摘除徽章或完成重认证。
### 8.4 CLI 一致性（强制）
- CLI 命令行表面属于规范的一部分；实现不得随意增删改子命令、flags 与退出码语义。
- [CES-8.4.1] 实现必须提供以下子命令：serve、mcp、hub sync、llm generate、run、score、validate、version；子命令集合变更视为规范版本变更。
- [CES-8.4.2] 退出码语义固定：0 成功；1 运行失败（I/O、解析失败、后端错误等）；2 用法错误（未知子命令、缺失或多余参数）。实现不得引入其他退出码语义。
- [CES-8.4.3] serve 启动横幅输出到 stdout；mcp 启动横幅输出到 stderr，stdout 完整保留给 JSON-RPC 2.0 流（CES-7.3），不得混入任何非协议输出。
- [CES-8.4.4] flags 命名与默认值固定：serve -addr（默认 :8080）；hub sync -url、-api-key；score -coverage-total（默认 100）、-coverage-exercised（默认 0）。新增 flag 不得改变既有 flag 语义。
- [CES-8.4.5] CLI 一致性必须由自动化测试锁死：子命令集合、退出码语义与 flags 表面变更时，测试必须失败，防止静默破坏兼容性。

## 第 9 章 · 变异实验规范（Mutation Experiment Specification, MES）

### 9.1 定位
变异实验是静态扰动：改动代码、运行测试、判定生死，证明测试集有效。变异与混沌共享 HPOV 范式与统一判定语义（CES-0.5）。

### 9.2 变异算子五分类（编码永久固定，守恒层）
| 编码 | 分类 | 定义 |
|---|---|---|
| M1 | Arithmetic 算术变异 | + - * / % 互换（AOR） |
| M2 | Relational 关系变异 | < <= > >= == != 互换与边界偏移（ROR） |
| M3 | Conditional 条件变异 | 逻辑与/或互换、条件取反（COR/LOR） |
| M4 | ReturnValue 返回值变异 | 返回零值/nil/反值（RVR） |
| M5 | Statement 语句变异 | 删除或复制语句（SDL） |

- [CES-9.2.1] 新算子必须归入 M1-M5 之一；不属于任何一类意味着新增算子类，属内核轨变更，须 RFC。
- [CES-9.2.2] 算子实现必须确定性：同一源位置 + 同一 seed 产出同一变异体。
- [CES-9.2.3] 变异体全局标识格式：mut:{file}:{line}:{col}:{class}。

### 9.3 变异评分
- [CES-9.3.1] 变异分 = 被杀死变异体数 × 10000 ÷ 非等价变异体总数（万分位定点，CES-4.1.2 同源纪律）。
- [CES-9.3.2] 等价变异体不计入分母：必须经 RFC 申报并由规范委员会确认，进入等价变异体登记册；门禁不设豁免开关。
- [CES-9.3.3] 全量覆盖门禁：变异杀死率 100%（即 Escaped = 0，CES-0.5.3）；低于 100% 必须在报告中逐条列出存活变异体。

### 9.4 执行与零抖动
- [CES-9.4.1] 变异体在隔离沙箱中执行；以 CPU 指令计数替代墙钟度量执行代价，性能噪音物理归零。
- [CES-9.4.2] 变异体选择、执行顺序由确定性 RNG（splitmix64）按 seed 驱动；同 seed 同代码版本的重跑结果必须完全一致。

### 9.5 AI 补测飞轮
- [CES-9.5.1] 存活变异体可作为补测输入投喂代码生成模型；生成用例必须真实杀死目标变异体并在 CI 复现后方可入库。
- [CES-9.5.2] AI 生成用例的权属归运行方项目所有；规范不主张权利（许可边界见 COMMERCIAL.md）。
- [CES-9.5.3] LLM 客户端必须实现 `LLMClient` 接口（`GenerateTest(mutant, source, feedback) → (testCode, err)`，feedback 携带上一轮失败原因，见 CES-9.5.5）；参考实现提供 OpenAI（Chat Completions API）与 Anthropic Claude（Messages API）两种客户端，均使用标准库 net/http，零外部依赖。
- [CES-9.5.4] LLM 客户端必须支持通过配置自定义 API 端点（BaseURL），以兼容 Azure OpenAI、代理网关与私有化部署；API Key 不得硬编码或写入日志。
- [CES-9.5.5] LLM 补测生成必须依次通过质量门禁：本地语法预检（AST 解析）→ 测试执行 → 杀死验证；任一门禁失败时，失败原因必须作为 feedback 传入下一轮生成（错误反馈闭环），禁止丢弃错误的盲重试。
- [CES-9.5.3] 禁止未人工核验的 AI 批量产出直接进入测试集（防投毒，见 SECURITY.md 威胁模型）。

## 附录 A · 状态机 TLA+ 模型（强制，CES-3.4）

模型覆盖第 3 章全部状态、合法迁移表与不变量；实现方须以模型检验工具（TLC 或等价工具）穷举检验并导出用例（CES-3.4.2）。Verdict 为唯一终态：除 Verdict 外不得出现死锁。

```tla
---------------- MODULE ces ----------------
(************************************************************)
(* Abate CES v0.1 状态机模型（附录 A，CES-3.4 强制发布）    *)
(* 覆盖第 3 章状态定义、合法迁移表与不变量。                *)
(************************************************************)
EXTENDS Naturals

CONSTANTS
    Pending, Preflight, Injecting, Observing, Recovering, Verdict

VARIABLES
    state,     (* 当前生命周期状态 *)
    injected   (* 是否残留注入副作用 *)

vars == << state, injected >>

Init == /\ state = Pending
        /\ injected = FALSE

(* Pending -> Preflight：受理进入准入检查 *)
Admit == /\ state = Pending /\ state' = Preflight /\ injected' = injected

(* Pending -> Verdict：准入前取消，判定 CANCELLED *)
Cancel == /\ state = Pending /\ state' = Verdict /\ injected' = injected

(* Preflight -> Injecting：准入通过（CES-3.1.4） *)
Pass == /\ state = Preflight /\ state' = Injecting /\ injected' = injected

(* Preflight -> Verdict：准入失败，判定 REJECTED（CES-3.1.4） *)
Reject == /\ state = Preflight /\ state' = Verdict /\ injected' = injected

(* 红线触发：适用状态内强制迁移 Recovering（CES-3.1.1） *)
RedLine == /\ state \in {Preflight, Injecting, Observing}
           /\ state' = Recovering /\ injected' = injected

(* Injecting -> Observing：注入窗口结束 *)
WindowEnd == /\ state = Injecting /\ state' = Observing /\ injected' = injected

(* Observing -> Recovering：观测结束 *)
ObserveEnd == /\ state = Observing /\ state' = Recovering /\ injected' = injected

(* Recovering -> Verdict：恢复完成，无残留（CES-3.1.2） *)
Recover == /\ state = Recovering /\ state' = Verdict /\ injected' = FALSE

(* Verdict 终态自环：终态非死锁（CES-3.4） *)
Done == /\ state = Verdict /\ UNCHANGED vars

Next == Admit \/ Cancel \/ Pass \/ Reject \/ RedLine
        \/ WindowEnd \/ ObserveEnd \/ Recover \/ Done

Spec == Init /\ [][Next]_vars

(* 不变量 1：状态取值合法 *)
TypeOK == state \in {Pending, Preflight, Injecting, Observing, Recovering, Verdict}

(* 不变量 2：终态无残留（CES-3.1.2） *)
ResidueFree == state = Verdict => injected = FALSE
================
```

模型检验义务：穷举检验 TypeOK 与 ResidueFree；除 Verdict 外无死锁；RedLine 动作在适用状态内始终使能（红线不可旁路）。允许以 Quint 等价模型替代，语义不得弱于本模型（CES-3.4.1）。
